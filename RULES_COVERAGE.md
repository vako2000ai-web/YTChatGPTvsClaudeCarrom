# Правила и границы модели v0.3

Опорные документы: [Laws of Carrom, AICF](https://www.indiancarrom.co.in/laws-of-carrom/) и [Senior changes](https://www.indiancarrom.co.in/new-version-rules/), просмотрены 11.10.2026. Программа реализует одиночную игру двух ИИ. Это цифровая интерпретация правил с виртуальным судьёй, а не сертифицированная федерацией настольная система. Матрица включает применимые разделы и явно отделяет физические действия людей.

Профили: `icf` — 15 секунд на решение; `aicf-senior` — 10 секунд. `house` сохраняет поведение v0.2. Матч — `--official-match`; отдельный борд запускается без этого флага. Технические лимиты обозначаются `*_aborted`, очки за них не начисляются.

| 37–42 | Начальный выбор задаёт `--first-player`; пробные борды не запускаются. Queen в центре, раскладка автоматическая. Жеребьёвка дополнительного борда воспроизводима, результат записывается. |
| 43–47 | Контакт страйкера фиксирует разбитие; три попытки; неудачная попытка без контакта; белый цвет у разбивающего. |
| 48–51 | Очередность, цвет/позиция в shared state, таймер, явное событие `out_of_turn`. |

| 62–64 | `technical_foul(offender)` без удара и `resolve(proper=False)` при ударе; отдельные сценарии и состояние долга. |
| 65–71 | События `overboard` и возврат Queen/своей фишки первыми, центр/ближайшая свободная позиция. Слои фишек, кант, вертикальные падения исключены двумерной физикой. |
| 72–78 | Страйкер, свои/чужие фишки, правильный/неправильный удар; немедленное погашение доступного долга. |
| 79–90 | Раздельные места возврата: центр для Queen/overboard и внешнее кольцо для dues; отсутствие места откладывает возврат. Виртуальный соперник всегда требует доступные штрафы и дополнительные очки, не отказывается от dues. Размещение мгновенно и детерминировано, без жестов/пальцев и ошибок человека. |
| 91 | Явное судейское событие `left_seat`. |
| 92–101 | Допуск Queen, первый свой coin вместе с Queen, немедленное/следующее покрытие, непокрытие, Queen+страйкер, повтор покрытия при own+страйкер. |
| 102–112 | Матрица последних фишек: обеих сторон, Queen на борде/покрытая, страйкер, неправильный удар и порог очков. Решение перед возвратом dues. |
| 113–120 | Pocket/overboard, удаление страйкера после остановки; неизменяемое оборудование. Повреждения дерева и вертикальные прыжки не генерируются симуляцией. |
| 121–126 | Явные события `play_during_appeal`, `disturbed_board`; часы и запрет следующего удара во время физики; чужой coin завершает ход по наблюдению виртуального судьи. |
| 127–136 | Действия агента ограничены одной скоростью страйкера и допустимой линией; прямое изменение доски недоступно. Общение партнёров doubles, зрители и предметы в руках отсутствуют в singles API. |
| 137–143 | `pass_turn`, заблокированная baseline, отмена борда/переигровка; `Tournament.referee` для сдачи игры/матча и дисквалификации. Перерыв людей не задерживает автоматический матч на 10 минут. |
| 144–151 | Организационная процедура письменного протеста/пошлины не симулируется; upheld protest перед текущим завершением борда может быть передан как `protest_upheld`. Отмена уже записанных прошлых бордов требует решения организатора и повторного запуска, автоматического пересчёта прошлых результатов нет. |

Для событий `referee` и ручных нарушений предоставлен Python-интерфейс, а не публичный параметр ответа ИИ. Публичный ответ ИИ по-прежнему содержит только `x`, `angle`, `power`, `comment`. Симуляция не позволяет агентам касаться доски руками, менять оборудование или выполнять удар за оппонента.

Адаптации протокола: неправильно сформированный ответ, невалидная позиция, ошибка API или превышение дедлайна приводят к пропуску/штрафу по профилю. После шести последовательных ошибок официальный борд технически прекращается. Это правило автоматизации, не дополнительная спортивная победа. Таймер включает API-запрос, проверку и публичный комментарий; сетевые повторы отключены. Неограниченный физический расчёт заменён пределом 15 секунд; таймаут физики сохраняется в журнале и требует проверки записи.

`tests/test_official_rules.py` содержит ожидаемые результаты сценариев отдельно от расчёта движка. Успех тестов не доказывает точность коэффициентов трения для всех физических досок. Следующее исследование — сопоставление симуляции с размеченными реальными ударами и экспертный просмотр спорных трактовок.
