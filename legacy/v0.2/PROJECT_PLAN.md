# Carrom AI Showdown — план разработки

Дата: 11 октября 2026. Рабочая папка: `C:\Work\YTChatGPTvsClaudeCarrom`.
Текущий этап: 0.2.0 — развитие обнаруженного архива 0.1, автоматический MVP.

## Цель продукта

Полноценный Carrom для Windows 11: ChatGPT и Claude самостоятельно выбирают
позицию страйкера, угол и силу. Движок рассчитывает физику и применяет правила.
Матч и серия проходят без вмешательства человека; состояние и решения доступны
для проверки честности и монтажа YouTube. OBS/CapCut — внешние средства производства.

## Принципиальные ограничения 0.2

Это домашние правила. Счёт HUD — количество удержанных фишек, не официальный
турнирный счёт. Queen не даёт бонусных очков. Одновременное попадание queen и
своей фишки сразу покрывает queen, даже если это первая фишка игрока. Последняя
фишка возвращается, если queen ещё не покрыта. Попадание страйкера возвращает
все новые свои фишки плюс одну ранее взятую/долг. Эти решения упрощают автоматический
прототип и требуют замены/проверки для официального ruleset.

Возврат идёт по центральной спирали, а не выбирается противником/судьёй.
Лимит ходов даёт ничью, даже если один игрок набрал больше фишек.
Серии пока не меняют цвета/стороны; смена стартующего игрока не устраняет все
позиционные преимущества. Сырые HTTP ответы/видео/полный покадровый replay,
денежная стоимость, восстановление после падения и Windows exe пока отсутствуют.
JSONL воспроизводим как журнал ходов, но не является полноценным replay-плеером.
При закрытии с ожидающим API worker запрос может ещё завершиться до timeout;
в журнале будет match_aborted, поздний результат не применяется.

## Этапы и критерии приёмки

### 0.2.1 — стабилизация физики и жизненного цикла (P0)

1. Калибровать геометрию луз, рикошет, массу, трение по записанным примерам.
2. Добавить матрицу corner/edge shots, максимальной силы и размещения рядом с фишками.
3. Проверить реальные GUI на Windows 11, DPI scaling, 60 FPS и длинные комментарии.
4. Ввести статус деградации при частых ошибках API и лимит подряд неудачных запросов.
5. Упаковать ключевые зависимости в проверяемый lock с wheel hashes; текущий freeze
   фиксирует среду проверки, но не является универсальным cross-platform lock.

Приёмка: 100 demo-матчей завершаются, ID фишек не теряются/не дублируются,
нет зависаний, физических таймаутов и пересечений при возврате; UI отвечает на ESC.

### 0.3 — официальный ruleset Carrom (P0)

Основа исследования: Laws of Carrom на сайте Indian Carrom Federation
https://www.indiancarrom.co.in/laws-of-carrom/ . Зафиксировать редакцию правил и
составить таблицу «пункт → состояние/событие → тест». Не копировать полный текст правил.

1. Отдельный selectable ruleset, сохранив домашний режим для сравнения/старых логов.
2. Право на queen после первой своей фишки, исключения первого попадания,
   долги/штрафы/неправильный удар, queen+striker+own/opponent combinations.
3. Правила break, baseline circles, законные направления и размещение страйкера.
4. Последняя фишка/queen/opponent simultaneous pocketing и поражение доски.
5. Установленные размеры оборудования, размещение dues, фишки за бортом,
   rolling/overlap; формально описать адаптацию 3D ситуаций в 2D.
6. Очки за доску, queen bonus и его ограничения, смена сторон, несколько досок/сетов.

Приёмка: сценарии на каждый реализованный пункт, независимая проверка правил,
в документации нет заявления о полном соответствии до завершения матрицы.

### 0.4 — честный и надёжный API-матч (P0)

1. Согласованный live smoke с действительными ключами и выбранными model IDs.
2. Проверить отказы, truncated outputs, timeouts, 429/5xx, доступ к моделям;
   ограниченные одинаковые retries с backoff и общим wall-clock budget.
3. Сохранять response ID, model version, safe raw model payload (без credentials),
   usage включая reasoning/cache tokens; отдельно учитывать диагностический ответ.
4. Версионировать prompt/state/action; сохранять hashes настроек и версии зависимостей.
5. Равные лимиты времени/токенов/инструментов; смена цветов и начинающего игрока.
6. Указать цели бюджета в конфиге: max requests, total token budget,
   стоимость по вручную подтверждённым тарифам и предел серии.

Приёмка: контролируемая короткая live серия без fallback, журнал позволяет
идентифицировать каждое решение; принудительные ошибки не выдают технический
провал за спортивную победу, отдельно отражены в статистике.

### 0.5 — стратегия и объективное сравнение (P1)

1. Геометрические кандидаты: прямой удар, ghost-ball, банк, blockers и safety.
2. Sandbox-копия физики для оценки кандидатов; одинаковый доступ обеим моделям.
3. Два формата сравнения: только state→move и state+одинаковые tools→move.
4. Отдельные сильные/слабые offline baseline agents без выдачи за LLM.
5. Набор зафиксированных позиций; оценка legal moves, own pocket rate, foul rate,
   latency, token cost; 20–100 парных матчей со сменой сторон.

Приёмка: воспроизводимые отчёты, одинаковые позиции/бюджет, интервалы неопределённости;
не заявлять превосходство модели по одному выигрышу.

### 0.6 — replay, турниры и статистика (P1)

1. Save/resume с версией состояния и запретом повторного списания API при replay.
2. Покадровые snapshots или детерминированное воспроизведение на конкретной версии Pymunk.
3. Best-of-3/5, round robin, расписание, seeds, обмен цветами, graceful resume серии.
4. SQLite хранилище матчей, модель/версия/ruleset/mode и метрики ошибок.
5. Экспорт JSON/CSV/таймкодов; replay timeline, pause/seek/speed/highlight.

Приёмка: replay не вызывает API и совпадает с исходным матчем; прерванная серия
возобновляется без потери статистики/повторного запроса ранее сохранённого решения.

Приёмка: записанный автоматический матч, читаемый HUD, синхронные звук/субтитры,
